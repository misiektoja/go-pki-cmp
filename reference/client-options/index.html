    Client options¶

    Options of client.NewClient apply to every call of that client. Request options apply to one call. The package documentation describes each in full.

    Client options¶

    Option Default Effect
    WithTrustedCAs None Anchors for signed responses and issued certificates
    WithRecipient NULL-DN CA name in the request header. Many CAs route on it
    WithResponseProtection pkicmp.ProtectionAny Requires MAC or signature protection on every response
    WithExtraCerts None Certificates added to extraCerts of every request
    WithServerCerts None CA protection certificates known out of band, for responses that do not carry them
    WithoutCAPubsTrust Off Keeps the CA certificates in caPubs of a MAC-protected response from becoming anchors
    WithSenderKIDMismatch Off Accepts a signed response whose senderKID names none of the candidate certificates
    WithSHA1Signatures Off Accepts responses signed with SHA-1
    WithMACIterationLimits 100 to 1000000 Accepted MAC iteration counts in responses, for PBMAC1 multiplied by the PRF blocks of the key length
    WithMaxPolls 60 Poll attempts before the call gives up
    WithCheckAfterLimits 1 second to 1 hour Clamps each wait the CA asks for
    WithMaxResponseBytes 10 MiB Largest accepted response body. Zero or less disables the limit
    WithHTTPClient The default transport with a 120 second timeout The HTTP client, for TLS settings, a proxy or another timeout
    WithRegistrationAuthority Off Wraps every request in a nested message signed by a registration authority

    To send a MAC iteration count outside the default range, set it on the credentials with pkicmp.WithMACIterationCount and widen pkicmp.WithMACIterationLimits to match.

    Request options¶

    Option Effect
    WithSender Sender name in the header. A signed request otherwise names the subject of its protection certificate
    WithSenderKID senderKID in every message, the reference of a shared secret
    WithTemplateSubject Subject in the certificate template
    WithTemplateExtension Adds an extension to the certificate template
    WithTemplateValidity Asks for a notBefore, a notAfter or both in the certificate template of an ir, cr or kur. The CA decides the validity it grants
    WithCertProfile Names a certificate profile in the header
    WithOldCertificate The certificate a key update replaces, for custom credential types
    WithGeneralInfo Adds items to generalInfo of the request header, after the certProfile
    WithCertReqID The certReqId of an ir, cr or kur, which the CA must repeat. Default 0
    WithPOPHash The digest of the signature proof of possession of an RSA or ECDSA key. Default by key type
    WithDeferredPolling Returns an ir, cr, kur or p10cr at the first waiting answer with the state for ResumeEnrollment
    WithImplicitConfirm Asks for implicit confirmation. When the CA grants it, no certConf is sent and EnrollResult.ImplicitConfirm is true
    WithInvalidityDate Adds the invalidityDate CRL entry extension to a revocation request, the time the certificate became invalid

    The digest of signature protection is chosen the same way on the credentials with pkicmp.SignatureCredentials.WithHash.

    Test aids¶

    These request options send deliberately wrong messages, to test how a CA handles them. They change nothing unless given. Do not use them in production.

    Option Effect
    WithCertConfStatus Sends a statusInfo in the certConf, such as a rejection. A CA must answer a rejection with pkiConf (RFC 9483 section 3.6.1). The call then returns the certificate
    WithMessageMutator Changes every message of the call before it is protected: the first request and any popdecr, pollReq and certConf. The function gets the message and the response it answers
    WithProtectedMessageMutator Changes every message after it is protected and before the nested message of WithRegistrationAuthority wraps it, for example to remove the protection

    The client verifies each response against the message as changed. A mutator that returns an error stops the call before the message is sent. A changed certConf that the CA refuses ends in a ConfirmationError that holds the certificate. ResumeEnrollment applies them to its pollReq and certConf messages. Its first pollReq answers a response the client did not keep, so the mutators get nil for it.

    // Send a certConf whose certHash does not match the certificate.
wrongHash := client.WithMessageMutator(func(msg, _ *pkicmp.PKIMessage) error {
    if msg.Body.Type != pkicmp.BodyTypeCertConf {
        return nil
    }
    conf, err := msg.Body.CertConf()
    if err != nil {
        return err
    }
    (*conf)[0].CertHash[0] ^= 0xff
    msg.Body = pkicmp.NewCertConfBody(conf)
    return nil
})
_, err := c.SendIR(ctx, key, creds, wrongHash)
// A CA that follows RFC 9483 refuses it with badCertId.
